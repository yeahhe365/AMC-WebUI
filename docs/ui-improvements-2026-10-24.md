# UI 布局、视觉与引导修复

本轮实现用户选择的 A（布局修复）和 D（视觉与引导完善），延续既有主题、组件和操作入口。

## 布局

- 顶部模型区域按剩余宽度收缩，长名称截断显示，保留完整的提示和无障碍名称。
- 模型菜单按真实尺寸调整横向位置；空间不足时向上展开，并根据视口和滚动容器的可见范围限制列表高度。可选详情卡片在空间不足时隐藏。保留原有键盘导航。
- 手机输入工具栏分为两行，两组按钮可以换行排列。
- 手机设置使用分类选择器、搜索、关闭和高级模式按钮，顶部高度由约 211px 减至 105px。桌面分类保持原结构。
- 自动命名卡片使用一行标题和独立开关，说明置于下方。
- Google 设置使用外层内容容器统一滚动，固定设置标题；搜索定位和分类滚动位置仍使用同一容器。

## 视觉与引导

- 根据后续要求，首页恢复原来的欢迎页，移除了本轮新增的说明、示例卡片和连接设置入口。
- 外观预览使用聊天中的 Markdown 渲染器展示代码、强调、行内代码、引用和表格，字体与字号遵循设置。
- 密码显示按钮采用当前界面语言；工具栏推理模式文案移至初始界面翻译包，避免首次打开设置前显示翻译键。
- 文件库区分首次添加文件与筛选无结果，分别展示上传引导与清除筛选操作。
- 新增文案覆盖 en、zh、ja、ko、es、fr、de。

## 检查与交付

- Prettier、TypeScript、ESLint、多语言覆盖检查通过。
- 生产构建通过；未修改依赖和后端逻辑。
- Chrome 中检查了 320×568、390×844 和桌面布局。桌面截图使用 1440×900 模拟窗口，浏览器既有缩放对应约 1309×818 CSS 像素。
- 320px 下头部模型菜单位于 x24–312；设置模型菜单修复后约为 x33–287、y105–314，位于可见内容区域内。
- Google 设置在桌面和手机均确认只有一个内容滚动区域；检查了设置分类切换、搜索跳转、自动命名卡片和德语长文案。
- 预览 DOM 确认包含实际 strong、em、blockquote 和 table；浅色、深色均进行目视检查。
- 检查了资料库的两种空状态。
- 独立只读审查及菜单修正的复查未留待处理问题。
- 更新既有预览测试的异步渲染和显示内容断言；本轮未新增或运行自动化测试。真实手机软键盘、触摸手势和屏幕阅读器未验证。
- 使用现有 Compose 项目与原环境配置重新构建部署；不读取或输出密钥，不调用模型 API。

实现保留在 `codex/comprehensive-optimization` 分支，没有合并或推送。

## 2026-10-26 模型菜单修复

- 顶部区域位于消息操作栏和输入框上方、手机侧边栏遮罩下方，解决警告、重试、复制及删除图标覆盖模型列表的问题。
- 详情卡片区分“当前选择”和“正在查看”，预览时说明需要点击列表才会切换。跨服务商存在同名模型 ID 时，采用预览状态，避免误标具体连接为当前选择。
- 鼠标移到详情卡片时保持预览，支持滚动阅读；方向键导航接管预览，关闭后重置。详情高度受可用空间约束。
- Chrome 使用本地示例错误消息复现：修复前按钮可穿透菜单；修复后重试、复制、删除三个按钮位置均命中上层模型列表。确认了预览、键盘确认选择、Escape 关闭，以及手机侧边栏遮罩覆盖关系。
- 类型、ESLint、格式、多语言覆盖检查和生产构建通过；独立源码复查无待处理问题。本轮未运行自动化测试。
- 使用现有 Compose 项目重新构建 Web 容器；API 与 Web 均健康，首页及健康接口返回 200。
